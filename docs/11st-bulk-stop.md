# 11번가 셀러오피스 일괄 판매중지 사용법

판매상품 목록을 **500개씩 보기 → 전체 선택 → 판매중지** 순서로 자동 반복하는 브라우저 콘솔 스크립트입니다.
10회 반복하면 약 5,000개 상품이 처리됩니다.

- `scripts/11st-inspect.js` — 화면 구조 진단(읽기 전용). 아무것도 변경하지 않습니다.
- `scripts/11st-bulk-stop.js` — 실제 자동화 스크립트.

---

## 시작하기 전에

**판매중지는 되돌리기 번거로운 작업입니다.** 5,000개를 한 번에 중지하면 다시 판매하려면 같은 규모의 재판매 처리가 필요하고,
상품에 따라 재승인·랭킹 초기화가 뒤따를 수 있습니다. 아래 순서대로 **소량 확인 → 전량 실행** 을 권합니다.

1. 셀러오피스에서 **상품관리 → 판매상품 조회/수정** 화면을 엽니다.
2. **판매상태 필터를 `판매중` 으로 지정**하고 조회합니다.
   - 이게 핵심입니다. 처리된 상품이 목록에서 빠져야 다음 500개가 올라옵니다.
   - 필터가 없으면 이미 중지된 상품을 계속 다시 선택하게 되어 무한 반복됩니다.
3. 조회된 전체 건수를 메모해 두세요. 나중에 결과를 대조할 기준이 됩니다.

---

## 1단계 · 화면 진단 (선택이지만 권장)

목록 화면에서 `F12` → **Console** 탭 → `scripts/11st-inspect.js` 내용 전체를 붙여넣고 Enter.

출력되는 내용:
- 목록 개수 선택 박스와 옵션 목록 (500 옵션이 있는지)
- 전체선택 체크박스 후보
- "판매중지" 버튼 후보와 화면의 모든 버튼 텍스트

여기서 500 옵션이나 판매중지 버튼이 안 잡히면, 출력 결과를 알려주세요. 선택자를 맞춰 드립니다.

> Chrome이 붙여넣기를 막으면 콘솔에 `allow pasting` 을 먼저 입력하고 Enter 를 누르세요.

---

## 2단계 · 안전 확인 (DRY RUN)

`scripts/11st-bulk-stop.js` 를 **그대로** 콘솔에 붙여넣고 Enter.

기본값이 `dryRun: true` 라서 **500개씩 보기 설정과 전체 선택까지만 수행하고, 판매중지는 누르지 않습니다.**

확인할 것:
- `선택된 상품: 500 / 화면 행 500` 처럼 예상한 숫자가 나오는지
- `찾은 판매중지 버튼: <button> "판매중지"` 가 제대로 잡히는지

---

## 3단계 · 실제 실행

DRY RUN 결과가 정상이면, 스크립트 상단 `CFG` 의 값을 바꿔서 다시 붙여넣습니다.

```js
const CFG = Object.assign({
  dryRun: false,   // ← true 에서 false 로
  batches: 1,      // ← 처음에는 1회만 (500개) 돌려보고 결과 확인
  pageSize: 500,
  ...
```

**첫 실행은 `batches: 1` 로 500개만** 처리하고, 셀러오피스에서 실제로 판매중지가 됐는지 눈으로 확인하세요.
문제가 없으면 `batches: 10` 으로 올려 나머지를 처리합니다.

### 실행 중 중단

```js
__ST11.stop()
```

콘솔에 입력하면 진행 중인 배치를 마치고 멈춥니다.

### 진행 상황 확인

```js
__ST11.state   // { aborted, processed, batchesDone }
```

## 설정값

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `dryRun` | `true` | `true` 면 선택까지만 하고 판매중지는 실행하지 않음 |
| `batches` | `10` | 반복 횟수. 500 × 10 = 약 5,000개 |
| `pageSize` | `500` | 한 페이지 상품 수. 500 옵션이 없으면 가장 큰 값으로 자동 대체 |
| `batchDelayMs` | `3000` | 배치 사이 대기(ms). 서버가 느리면 5000~8000 으로 올리세요 |
| `waitTimeoutMs` | `40000` | 목록 갱신 대기 최대 시간(ms) |
| `stopLabels` | `['판매중지', ...]` | 판매중지 버튼 텍스트 후보 |
| `confirmLabels` | `['확인', '예', ...]` | 확인 팝업 버튼 텍스트 후보 |

붙여넣기 전에 아래처럼 미리 지정해도 됩니다.

```js
window.__ST11_CFG = { dryRun: false, batches: 3, batchDelayMs: 6000 };
// 그 다음 11st-bulk-stop.js 붙여넣기
```

## 스크립트가 하는 일

1. 화면(및 동일 출처 iframe)에서 목록 개수 `<select>` 를 찾아 500으로 설정하고 `change` 이벤트 발생
2. `thead` 의 전체선택 체크박스를 클릭. 각 행에 전파되지 않으면 행 체크박스를 개별 클릭으로 대체
3. 선택된 개수를 세어 로그 출력
4. "판매중지" 버튼 클릭. 이때 `window.confirm`/`alert` 를 잠시 자동 승인으로 바꾸고, 레이어 팝업이면 "확인" 버튼을 눌러 처리한 뒤 원복
5. 목록의 행 수·첫 행·마지막 행으로 만든 지문이 바뀔 때까지 대기해 갱신을 감지
6. 갱신되면 다음 배치로, 갱신되지 않으면 **안전을 위해 즉시 중단**

## 안전장치

- 기본이 DRY RUN
- 판매중지 버튼을 못 찾으면 실행하지 않고 종료
- 선택된 상품이 0개면 종료
- 목록이 갱신되지 않으면(처리 실패 가능성) 종료
- `__ST11.stop()` 으로 언제든 중단
- `confirm`/`alert` 덮어쓰기는 클릭 구간에서만 적용하고 `finally` 에서 원복

## 주의사항

- 브라우저 탭을 닫거나 다른 페이지로 이동하면 중단됩니다. 실행 중에는 탭을 그대로 두세요.
- 셀러오피스 화면 개편으로 버튼 이름이나 구조가 바뀌면 자동 탐지가 실패할 수 있습니다. 이때는 1단계 진단 결과가 필요합니다.
- 대량 요청이 짧은 시간에 몰리면 차단될 수 있습니다. 실패가 잦으면 `batchDelayMs` 를 올리세요.
- 11번가가 별도로 제공하는 엑셀 일괄수정(대량 상품 수정) 기능이 있다면, 그쪽이 공식 경로라 더 안전합니다. 이 스크립트는 화면 조작 자동화입니다.
